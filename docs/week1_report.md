# تقرير الأسبوع الأول — Lightweight SIEM

**تاريخ التقرير:** 2026-11-07
**نطاق الأسبوع:** خط الأنابيب الأساسي (Collector ← Normalizer ← Rule Engine ← Storage)

---

## 1. ماذا أنجزنا هذا الأسبوع؟

بنينا الجزء الأساسي من الـ SIEM: مساراً كاملاً يبدأ من **ملف سجل خام** وينتهي بـ **تنبيه مخزّن ومطبوع**. المسار (Pipeline):

```
ملف السجل (auth.log)
      │
      ▼
[1] collector/file_tail.py      يقرأ السطور الجديدة باستمرار (مثل tail -f)
      │  سطر خام (string)
      ▼
[2] normalizer/ssh_normalizer.py يحوّل السطر إلى JSON موحّد
      │  حدث (event dict)
      ▼
[3] rules/engine.py             يقيّم الحدث على قواعد rules.yaml
      │  تنبيه (alert dict) عند تحقّق شرط
      ▼
[4] storage/database.py         يحفظ الحدث والتنبيه في SQLite
      │
      ▼
[5] main.py                     يطبع التنبيه في الـ console
```

**النتيجة العملية:** عند إدخال 6 محاولات فاشلة من نفس الـ IP خلال 60 ثانية يظهر:

```
[ALERT][HIGH] BRUTE_FORCE_001: Brute force from 198.51.100.7: 6 failed logins in 60s.
```

**الاختبارات:** 27 اختبار وحدة كلها ناجحة (`python -m pytest`).

## 2. فائدة كل ملف

### ملفات الكود (كُتب هذا الأسبوع)

| الملف | فائدته | بلغة بسيطة |
|-------|--------|-----------|
| **`main.py`** | نقطة التشغيل و«المخابرة» بين كل الوحدات. يقرأ الإعدادات، يشغّل الـ tail، ويرسل كل سطر عبر باقي المراحل. فيه أيضاً دالة `process_line()` القابلة للاختبار ووضع `--once` لمعالجة الملف مرة واحدة. | «السير الذي يمرّر الشيء من مكان لآخر» |
| **`collector/file_tail.py`** | يقرأ ملف السجل **باستمرار** وينتظر السطور الجديدة (سلوك `tail -f`). الدالة `_open_log()` تفتح الملف وتحدد نقطة البداية، و`tail_file()` مولّد (generator) يسلّم سطراً بعد سطر. | «العين التي تراقب الملف ولا تفوّت أي سطر» |
| **`normalizer/ssh_normalizer.py`** | تحويل السطر الخام (نص غير منظّم) إلى قاموس JSON موحّد فيه 6 حقول: `timestamp, source_ip, username, event_type, status, raw_log`. يتعرّف على 3 أنماط: فشل دخول، نجاح دخول، و port scan — ويرجّع `None` لسطر غير معروف. | «المترجم»: لغات مختلفة → لغة واحدة مفهومة |
| **`rules/engine.py`** | يحمّل القواعد من الـ YAML ويقيّم كل حدث عليها. يبني **نافذة منزلقة** (sliding window): يحتفظ بتاريخ كل حدث في مجموعة (rule + IP) ويشطب الأقدم من النافذة الزمنية، ثم يقارن العدّاد بالحد المطلوب. يمنع تكرار التنبيه لكل سطر (تنبيه واحد لكل موجة هجوم). | «المحقق»: يجمع الأدلة خلال فترة وحكم إن كان كافية |
| **`rules/rules.yaml`** | ملف **البيانات** (ليس كوداً) يعرّف 4 قواعد: Brute Force، Port Scan، ارتباط (فشل→نجاح)، وهجوم بطيء. تعديل الأرقام أو إضافة قاعدة = تعديل هذا الملف فقط. | «قانون مكتوب»: تغيّر القانون دون إعادة بناء المحكمة |
| **`storage/database.py`** | غلاف SQLite ينشئ جدولي `events` و`alerts` ويوفر الدوال: `save_event`, `save_alert`, `get_recent_events`, `get_recent_alerts`, `count_events_by_type`. | «الأرشيف»: ذاكرة دائمة حتى بعد إغلاق البرنامج |
| **`config/siem.config.yaml`** | إعدادات قابلة للتعديل بدون لمس الكود: مسار السجل، مسار قاعدة البيانات، إعدادات الـ dashboard. | «لوحة إعدادات» |

## 3. قرارات تصميمية اتخذناها ولماذا

1. **قاعدة واحدة فقط من نوع `sequence` لم تُنفَّذ بعد** — محرك القواعد هذا الأسبوع يتعامل مع `threshold` فقط (عدّ داخل نافذة)، والارتباط متعدد الأحداث مهموم به الوحدة `correlation/` في الأسبوع 2. لهذا السبب القاعدة `LOGIN_ESCALATION_001` موجودة في الملف لكنها لم تُختبر بعد.

2. **تنبيه واحد لكل موجة** — بدون هذا، 100 سطر فشل = 100 تنبيه متطابق (إعاقة + False Positive مصطنع). الحل: علم `fired` يُصفّر عندما ينزل العدّاد تحت الحد.

3. **السطور غير المعروفة تُتجاهل** (`return None`) — السجلات الحقيقية فيها سطور كثيرة غير أمنية (cron، kernel...). تطبيعها غصباً يلوّث البيانات.

4. **تاريخ syslog بلا سنة** → نستخدم السنة الحالية؛ تاريخ LogHub بصيغة ISO يُقبل كما هو.

5. **التوثيق بالإنجليزية** (docstrings + type hints) حسب متطلبات المشروع، والتقرير بالعربية لفهمك أنت.
